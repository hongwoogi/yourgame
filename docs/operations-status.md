# 운영 상태 안내

상태: 운영 정책과 문구. 2026-08-31 사용자 요청에 따라 상태·API 오류 로그 점검을 구현하고 현재 작업의 5분 간격 후속 실행 `yourga-me`를 등록했다. 현재 Google 운영 origin 차단은 별도 미해결 상태다. 구현·실행·검증된 범위는 [인프라 기록](infrastructure-status.md)과 [Google 로그인 기록](google-login-setup.md)을 따른다. 아래의 참여자용 장애 안내 화면 전체를 구현한 것은 아니다.

## 목적과 말투

PC 오프라인이나 구독 한도 소진 등으로 제안 반영이 지연될 때 참여자에게 운영 문제임을 알린다. 사용자의 요청에 따라 농담의 대상은 운영자로 한정하고, 참여자의 제안이나 행동을 탓하지 않는다. 가벼운 놀림을 사용하되 인격 비하나 과한 욕설은 쓰지 않는다.

## 표시 구성

- 상태 표시: `SYSTEM ERROR · 업데이트 지연`
- 원인에 맞는 짧은 농담.
- 확인된 원인과 지연 영향에 대한 사실 설명.
- 확인 가능한 경우 기존 버전 플레이 버튼, 마지막 공개 버전, 다음 정규 시도 시각.
- 원인을 모르면 일반 지연 문구를 사용한다. 복구 예정 시각을 만들어내지 않는다.

## 원인별 문구

| 조건 | 농담 문구 | 사실 설명 |
| --- | --- | --- |
| 작업 PC 응답 없음 | **운영자 PC가 무단결근 중입니다. 게임보다 먼저 잠수 콘텐츠를 구현했네요.** | 업데이트 작업용 PC의 응답을 확인할 수 없어 새 버전 반영이 지연되고 있습니다. |
| 확인된 Codex 사용 한도 소진 | **운영자가 AI의 체력을 너무 믿었습니다. 지금은 운영자의 반성 턴입니다.** | Codex 사용 한도에 도달해 업데이트 작업이 대기 중입니다. 운영자에게 알리고 실행 여건이 회복되면 다시 검증을 진행합니다. |
| 원인 미확인 또는 복합 장애 | **게임은 진화 중인데, 운영은 아직 튜토리얼입니다.** | 운영 문제로 이번 업데이트를 반영하지 못하고 있습니다. 원인을 확인하고 있습니다. |
| 검증 실패 — 확장용 초안 | **운영자의 야심작이 품질검사에서 퇴짜를 맞았습니다.** | 이번 변경은 검증을 통과하지 못해 공개하지 않았습니다. |
| 인증 확인 필요 — 확장용 초안 | **운영자가 AI 사무실 출입증을 두고 왔습니다.** | 작업 계정 인증을 확인해야 하므로 업데이트 작업이 중단되어 있습니다. |
| 운영 재개 확인 | **운영자가 드디어 수습했습니다. 다음 진화를 준비합니다.** | 작업을 다시 실행할 수 있는 상태가 확인되었습니다. 반영과 검증을 다시 진행합니다. |

## 사실을 과장하지 않는 규칙

- PC 신호가 끊겼다는 사실만으로 전원이 꺼졌다고 단정하지 않는다. 공개 원인은 `작업 PC 응답 없음`으로 표시한다.
- 사용량 API 조회 실패나 원인 불명 오류를 `구독 한도 소진`으로 표시하지 않는다. 명확히 확인된 경우에만 해당 문구를 사용한다.
- 기존 게임이 실제 제공되는 경우에만 `기존 버전은 계속 플레이할 수 있습니다`를 표시한다. 최초 버전 공개 전에는 `첫 게임 공개가 지연되고 있습니다`로 표시한다.
- 제안 접수 성공이 확인된 경우에만 저장되었다고 안내한다. 접수 장애까지 발생했다면 제안 저장 실패 또는 재시도 필요를 별도로 표시한다.
- 다음 시도 예정 시각은 배포 또는 복구 보장이 아니다. 작업 재개만으로 `업데이트 완료`라고 표시하지 않는다.
- 운영 지연 안내는 개별 제안의 제외 사유가 아니다. 참여자용 순위·제외 사유 비공개 원칙을 유지한다.
- 공개 화면에는 스택 추적, 내부 경로, 인증 정보, 계정 식별 정보 또는 비공개 작업 원문을 표시하지 않는다. 상세 오류 기록은 운영자 대시보드에서만 확인한다.
- 정상적인 제안 수집 기간이나 반영할 변경이 없는 상태를 운영 장애로 표시하지 않는다.
- 농담 문구 자체는 오류 상태와 별개로 관리하며, 브라우저에 노출되는 게임 코드가 실제 운영 상태를 임의 변경하지 못하게 한다.

## 미정인 구현 세부사항

- 작업자 신호 주기, 응답 없음으로 판정할 시간과 일시적인 통신 실패 처리.
- 한도 소진과 인증 실패의 판정 기준, 복구 상태를 검증하는 방법.
- 운영 지연 중 미반영 요구와 새 회차 요구를 재검토하는 정확한 절차.

## 운영자 보고와 복구

- 확인된 실패는 이 Codex 작업에 보고한다. 발견 시각, 실패한 단계, 영향, 확인한 원인과 아직 모르는 사항, 진행 중인 조치를 짧게 적는다. 오류 메시지만으로 확인되지 않은 원인을 단정하지 않는다.
- 감시는 정상 응답과 실제 결과를 검사한다. HTTP 200, Git push 성공 또는 카운트다운 종료만으로 접수·공개 성공으로 표시하지 않는다.
- 동일한 장애는 상태 기록으로 묶고, 새 증상·원인 확인·복구 완료 때 갱신한다. 같은 실패를 매번 새 장애처럼 반복 통지하지 않는다.
- 일시적인 통신 오류는 짧고 제한된 재시도로 확인하고, 계속 실패하면 사실을 보고한 뒤 원인을 조사한다. 수정 뒤 같은 검증을 다시 통과해야 복구 완료로 기록한다.
- 안전하게 되돌릴 수 있는 코드·설정 수정과 검증은 계속 진행한다. 인증 재로그인, 결제·사용량 구매, 접근 권한 변경 또는 데이터 손실 위험처럼 운영자 개입이 필요한 경우에는 필요한 행동을 구체적으로 알린다.
- 앱의 후속 실행은 PC와 Codex 앱이 실행 중이어야 한다. 주기적 점검 사이의 지연, 앱·네트워크 장애나 구독 한도 때문에 확인 및 알림이 지연될 수 있다. 완전한 실시간 감지나 실패 없는 운영을 보장하지 않는다.

## 실패 시 정상 게임 제공

2026-08-31 후속 요청으로 확정한 정책이다. 첫 게임 공개 구현에 아래 안내와 게임 선택·복귀 기능을 포함한다. 현재는 공개 게임이 없으므로 실제 복귀 성공을 표시하지 않는다. 실행 조건과 검증은 [배포 절차](deployment-flow.md#마지막-정상-게임-유지와-자동-복귀)를 따른다.

| 확인된 상태 | 참여자 안내 | 제공 상태 |
| --- | --- | --- |
| 새 공개가 공개 전에 실패, 기존 게임 실행 정상 | 이번 업데이트에 실패했습니다. 정상 버전 {version}은 계속 플레이할 수 있어요. | 기존 정상 게임을 유지 |
| 공개 후 장애, 정상 버전 복귀와 실행 확인 완료 | 새 버전에서 문제가 발견되어 정상 버전 {version}으로 복귀했습니다. | 새 방문·플레이 시작에 정상 게임 제공 |
| 공개 후 장애, 복귀 진행 중 또는 결과 미확인 | 새 버전에서 문제가 발견되어 복구 중입니다. | 복귀 성공을 단정하지 않고 장애 버전의 새 플레이 중단 |
| 최초 공개 실패, 이전 정상 게임 없음 | 첫 게임 공개가 지연되고 있습니다. 접수된 제안은 보존됩니다. | 준비 화면 유지, 제안 접수 상태는 별도 표시 |

실패한 대상은 새 공개 시도다. 정상인 이전 게임을 실패 버전으로 표시하지 않는다. 운영자 보고에는 실패한 시도, 현재 제공 버전, 복귀 검증 결과를 따로 기록한다. 공개 안내에는 내부 배포 ID나 오류 원문을 노출하지 않는다.

복귀를 위해 로그인·제안·제출 횟수·버전별 세이브를 초기화하지 않는다. 플레이 중인 브라우저를 강제로 새로고침하거나 다른 버전의 세이브로 덮어쓰지 않는다. 안전 문제로 진행 중인 장애 게임도 중단해야 한다면 이유를 안내하고 정상 버전의 해당 세이브 또는 새 시작으로 전환한다. 기존 게임을 제공할 수 있어도 로그인·접수에 별도 장애가 남아 있으면 서비스 전체가 복구되었다고 표시하지 않는다.
