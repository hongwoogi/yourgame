# 운영 상태 안내

상태: 설계 및 문구 초안. 실제 오류 감지나 화면 구현은 아직 하지 않았다.

## 목적과 말투

PC 오프라인이나 구독 한도 소진 등으로 제안 반영이 지연될 때 참여자에게 운영 문제임을 알린다. 사용자의 요청에 따라 농담의 대상은 운영자로 한정하고, 참여자의 제안이나 행동을 탓하지 않는다. 가벼운 놀림을 사용하되 인격 비하나 과한 욕설은 쓰지 않는다.

## 표시 구성

- 상태 표시: `SYSTEM ERROR · 업데이트 지연`
- 원인에 맞는 짧은 농담.
- 확인된 원인과 지연 영향에 대한 사실 설명.
- 확인 가능한 경우 기존 버전 플레이 버튼, 마지막 공개 버전, 다음 정규 시도 시각.
- 원인을 모르면 일반 지연 문구를 사용한다. 복구 예정 시각을 만들어내지 않는다.

## 원인별 문구

| 조건 | 농담 문구 | 사실 설명 |
| --- | --- | --- |
| 작업 PC 응답 없음 | **운영자 PC가 무단결근 중입니다. 게임보다 먼저 잠수 콘텐츠를 구현했네요.** | 업데이트 작업용 PC의 응답을 확인할 수 없어 새 버전 반영이 지연되고 있습니다. |
| 확인된 Codex 사용 한도 소진 | **운영자가 AI의 체력을 너무 믿었습니다. 지금은 운영자의 반성 턴입니다.** | Codex 사용 한도에 도달해 업데이트 작업이 대기 중입니다. 실행 여건이 회복되면 다음 가능한 정규 회차에서 다시 시도합니다. |
| 원인 미확인 또는 복합 장애 | **게임은 진화 중인데, 운영은 아직 튜토리얼입니다.** | 운영 문제로 이번 업데이트를 반영하지 못하고 있습니다. 원인을 확인하고 있습니다. |
| 검증 실패 — 확장용 초안 | **운영자의 야심작이 품질검사에서 퇴짜를 맞았습니다.** | 이번 변경은 검증을 통과하지 못해 공개하지 않았습니다. |
| 인증 확인 필요 — 확장용 초안 | **운영자가 AI 사무실 출입증을 두고 왔습니다.** | 작업 계정 인증을 확인해야 하므로 업데이트 작업이 중단되어 있습니다. |
| 운영 재개 확인 | **운영자가 드디어 수습했습니다. 다음 진화를 준비합니다.** | 작업을 다시 실행할 수 있는 상태가 확인되었습니다. 다음 정규 회차에서 반영을 재시도합니다. |

## 사실을 과장하지 않는 규칙

- PC 신호가 끊겼다는 사실만으로 전원이 꺼졌다고 단정하지 않는다. 공개 원인은 `작업 PC 응답 없음`으로 표시한다.
- 사용량 API 조회 실패나 원인 불명 오류를 `구독 한도 소진`으로 표시하지 않는다. 명확히 확인된 경우에만 해당 문구를 사용한다.
- 기존 게임이 실제 제공되는 경우에만 `기존 버전은 계속 플레이할 수 있습니다`를 표시한다. 최초 버전 공개 전에는 `첫 게임 공개가 지연되고 있습니다`로 표시한다.
- 제안 접수 성공이 확인된 경우에만 저장되었다고 안내한다. 접수 장애까지 발생했다면 제안 저장 실패 또는 재시도 필요를 별도로 표시한다.
- 다음 시도 예정 시각은 배포 또는 복구 보장이 아니다. 작업 재개만으로 `업데이트 완료`라고 표시하지 않는다.
- 운영 지연 안내는 개별 제안의 제외 사유가 아니다. 참여자용 순위·제외 사유 비공개 원칙을 유지한다.
- 공개 화면에는 스택 추적, 내부 경로, 인증 정보, 계정 식별 정보 또는 비공개 작업 원문을 표시하지 않는다. 상세 오류 기록은 운영자 대시보드에서만 확인한다.
- 정상적인 제안 수집 기간이나 반영할 변경이 없는 상태를 운영 장애로 표시하지 않는다.
- 농담 문구 자체는 오류 상태와 별개로 관리하며, 브라우저에 노출되는 게임 코드가 실제 운영 상태를 임의 변경하지 못하게 한다.

## 미정인 구현 세부사항

- 작업자 신호 주기, 응답 없음으로 판정할 시간과 일시적인 통신 실패 처리.
- 한도 소진과 인증 실패의 판정 기준, 복구 상태를 검증하는 방법.
- 운영 지연 중 미반영 요구와 새 회차 요구를 재검토하는 정확한 절차.
