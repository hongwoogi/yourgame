# 공개 후 플레이·제안 화면 기준

상태: 2026-08-31 사용자가 PC에서 게임 옆에 제안창을 두는 기본 구성을 승인했다. 모바일 접속을 허용하고, 실제 게임은 최종적으로 9:16 세로 화면과 터치 조작에 맞춘다. 현재는 준비·제안 페이지이며 아래 기준을 기록하거나 화면 예시를 만든 것이 실제 게임 공개를 뜻하지 않는다.

## 지금 확정된 요구

- yourga.me는 모두의 제안으로 함께 변화시키는 하나의 PC·모바일 싱글플레이 로그라이크다. 개인별 생성 게임이나 멀티플레이로 설명하지 않는다. 구체적인 전투·성장·목표는 참여자 제안으로 정한다.
- 첫 화면에 제안 수집 → 요구 정리 → 자동 개발 → 실행 검증 → 공개 → 플레이 후 다시 제안의 흐름을 보여준다. 장르 범위와 충돌을 검토하며 모든 제안을 입력 즉시 그대로 실행하지 않는다.
- 게임 공개 뒤에는 같은 페이지에서 게임 플레이와 다음 변화의 제안 입력을 제공한다. 플레이는 비로그인으로 가능하고 제안 제출만 Google 로그인이 필요하다.
- 최근 60분 신규 제안 최대 3개, UTF-8 2,000바이트, 마감 전 수정 가능·삭제 불가, 로그인 후 전송 의도와 초안 보존 정책은 유지한다.
- 게임 표현은 [Teen 개발·참여 안전 기준](participation-safety.md)을 따른다. 제안 접수와 안전 승인·채택은 구분해 표시하고 안전 검토 전의 원문을 다른 참여자에게 공개하지 않는다.
- 영어를 기본으로, 한국 접속은 한국어로 자동 표시하고 우측 상단에서 수동 선택한다. 실제 게임의 HUD·조작 안내·일시정지·새 버전 안내도 [언어 지원 기준](localization.md)을 따른다. 언어를 바꿔도 진행 중인 판·세이브·제안 초안을 초기화하지 않는다.
- 검증 전에 실패하면 정상 게임을 유지하고, 공개 후 장애에는 마지막 정상 게임으로 복귀한다. 최초 게임이 없으면 준비 화면과 지연 안내를 유지한다. 게임·제안·세이브 기록을 삭제하지 않는다.

## PC와 모바일 배치

| 환경 | 게임과 제안창 | 조작 기준 |
| --- | --- | --- |
| 넓은 PC 화면 | 왼쪽 게임, 오른쪽 제안창을 기본으로 함께 표시 | 키보드·마우스 지원, 세로 게임 화면을 늘이거나 자르지 않음 |
| 모바일·좁은 화면 | 위쪽 게임, 아래쪽 제안창을 한 페이지에 배치 | 터치 조작, 제안창으로 이동하는 접근점 제공, 가로 회전 강제 없음 |
| 게임 확대 | 사용자가 선택한 동안 게임에 집중하고 제안창으로 돌아가는 동작 제공 | 입력 중인 초안을 보존하고 확대 해제로 기본 배치 복귀 |

9:16은 **게임 실행 영역**의 가로:세로 비율이다. 웹페이지 전체를 9:16으로 고정하지 않는다. PC에서도 같은 게임 규칙과 세로 시야를 유지하고 주변 여백을 허용한다. 작은 모바일 화면에는 게임 영역을 비율대로 축소하고, 터치 버튼과 핵심 정보는 읽고 누를 수 있는 크기를 유지한다. 게임 조작을 호버나 키보드 전용 동작에 의존시키지 않는다.

현재 준비 페이지부터 모바일에서 카운트다운·설명·로그인·신규 제안·수정에 접근할 수 있게 한다. PC 전용 차단 안내는 제거한다. 모바일 가상 키보드, 한글 조합, 긴 문장, 로그인 모달, 화면 회전과 안전 영역을 고려하며 입력 글꼴은 최소 16px을 기본으로 한다. 긴 설명과 흐름도는 좁은 화면에서 세로로 재배치한다.

## 공개 상태에 따른 변화

운영 주소는 유지하고 실제 공개 상태에 따라 중심 내용을 바꾼다.

| 상태 | 주된 화면 | 제안과 상태 표시 |
| --- | --- | --- |
| 첫 게임 공개 전 | 로그라이크 소개, 첫 공개 카운트다운, 제안 입력, 개발 흐름도 | 모집 상태와 실제 접수 가능 상태를 구분 |
| 첫 게임 공개 후 | 9:16 게임 실행 영역, 현재 제공 버전, 조작 안내 | PC는 옆, 모바일은 아래 제안창에 남은 횟수·바이트·수집 마감·본인 제안 표시 |
| 다음 버전 제작·검증 중 | 정상 게임을 계속 플레이 | 다음 공개 목표와 제작 상태를 표시하되 성공으로 단정하지 않음 |
| 업데이트 실패 | 마지막 정상 게임을 제공 | 실패한 시도와 현재 제공 버전을 구분해 안내 |
| 운영 점검·종료 | 운영자가 정한 점검·종료 안내 | 신규·수정 제안과 새 개발·공개 중지, 로그인·관리자 복구 접근 유지 |

공개 후에는 긴 첫 모집 소개와 첫 공개 카운트다운을 화면의 중심에서 내리고 게임이 중심이 되게 한다. 개발 흐름 설명은 필요할 때 확인할 수 있게 남긴다. 관리자 기능은 별도의 보호된 `/admin`에서 제공한다.

후속 투표·기여도 요청은 같은 참여 패널에 제안하기·다른 제안·내 기여도를 연결하는 방향으로 정리한다. 모바일의 9:16 게임을 가리거나 초안을 잃게 하지 않는다. 공개 동의·검토·투표 예산·반영 보상은 [별도 설계](voting-and-contribution.md)를 따르며 현재 투표·리더보드가 구현되었다는 뜻은 아니다.

## 플레이와 입력의 기본 동작

배치 승인에 이어 구현할 때 적용할 기본값이다. 실제 게임이 없는 현재 준비 화면에 일시정지·게임 확대 기능이 이미 있다고 표시하지 않는다.

- 기본 PC 화면은 게임 영역과 오른쪽의 제안창을 나란히 둔다. 모바일에서는 같은 페이지 아래의 제안창으로 이동한다.
- 제안창에 입력하거나 로그인 모달을 열면 게임을 일시정지하고 조작 입력을 차단한다. 한글 입력, Space·Enter·방향키가 게임 조작과 동시에 실행되지 않게 한다. 게임을 재개하는 행동은 분명한 버튼으로 제공한다.
- 모바일에서는 가상 키보드로 게임을 가리더라도 초안과 일시정지 상태를 유지한다. 입력창에서 벗어난 것만으로 재개하지 않고 재개 버튼을 제공한다.
- 한 판 종료 후에 제안창을 강조할 수 있지만 제출을 강제하지 않는다. 로그인만으로 작성 중인 제안을 전송하지 않는다.
- 플레이 중 새 버전이 공개되어도 강제 새로고침하거나 진행 중인 버전을 바꾸지 않는다. 새 버전 안내와 전환 행동을 제공하고 버전별 세이브는 분리한다.
- 아카이브는 플레이 전용이다. 제안 대상은 현재 제공 버전임을 명시한다. 초안 작성 중 현재 제공 버전이 바뀌면 이전 대상을 표시하고 사용자가 확인한 뒤 전환하게 하며 초안을 조용히 다른 버전에 붙이지 않는다.

## 화면 구현 전에 필요한 연결

현재 `/api/status`는 `game.published=false`를 반환하며 실제 게임 선택·산출물·세이브·실행 신호는 없다. 자정 도달이나 HTML 변경만으로 게임 화면을 공개해서는 안 된다. 검증된 게임의 식별자·실행 주소·현재 제공 버전과 제작 상태를 서버의 공개 상태로 연결해야 한다.

게임과 제안창을 같은 화면에 두더라도 실행 권한은 분리해야 한다. 현재 보안 정책은 Google 외 게임 프레임을 허용하지 않으며, 생성 게임을 계정 화면의 스크립트로 합치면 제안 초안과 계정 API에 접근할 수 있다. 게임 실행 영역을 계정·제안 영역과 다른 출처로 격리하고, 필요한 로딩·일시정지·재개·종료 신호만 검증하여 전달하는 설계를 먼저 적용한다. 실제 실행 주소와 세이브 중계 방식은 아직 확정하지 않았다.

공개 성공, 현재 제공 게임, 플레이 중인 게임, 제안 대상 회차·버전은 서로 다른 값이다. 새 공개나 복귀로 로그인 세션·제출 횟수·제안·버전별 세이브를 되감지 않는다. 첫 게임 구현 때 [공개 실행 절차](launch-runbook.md)와 [실패 복귀 규칙](deployment-flow.md)을 함께 검증한다.

## 첫 게임 검증 기준

PC 키보드와 모바일 터치 양쪽에서 9:16 표시·시작·플레이·종료·입력 중 정지·재개를 검증한다. 좁은 화면과 가상 키보드가 열린 상태에서도 제안 초안·남은 횟수·오류 안내를 확인할 수 있어야 한다. 이미 합의한 비로그인 플레이, Google 제출, 제출 제한, 강제 버전 전환 금지와 세이브 분리는 유지한다.
