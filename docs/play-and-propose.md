# 공개 후 플레이·제안 화면 기준

상태: 2026-08-31 후속 요청을 반영했다. PC에서는 게임 미리보기·투표·제안 입력·기여도 순위를 한 화면에 모으고, 투표를 입력창 위에 둔다. 모바일은 같은 기능에 세로 스크롤로 접근한다. 현재는 준비·제안 페이지이며 흰 9:16 캔버스가 실제 게임 공개를 뜻하지 않는다.

## 지금 확정된 요구

- yourga.me는 모두의 제안으로 함께 변화시키는 하나의 PC·모바일 싱글플레이 로그라이크다. 개인별 생성 게임이나 멀티플레이로 설명하지 않는다. 구체적인 전투·성장·목표는 참여자 제안으로 정한다.
- 첫 화면의 작은 4단계 줄로 제안·요구 정리 → Codex 자동 개발 → 검증·공개 → 플레이·다시 제안을 보여준다. 이는 예정된 개발 방식이며 실시간 진행 표시가 아니다. 유사 요구·충돌·장르 범위를 정리하며 모든 제안을 입력 즉시 그대로 실행하지 않는다.
- 게임 공개 뒤에는 같은 페이지에서 게임 플레이와 다음 변화의 제안 입력을 제공한다. 플레이는 비로그인으로 가능하고 제안 제출만 Google 로그인이 필요하다.
- 최근 60분 신규 제안 최대 3개, UTF-8 2,000바이트, 마감 전 수정 가능·삭제 불가, 로그인 후 전송 의도와 초안 보존 정책은 유지한다.
- 공개 페이지에서는 별도 공개 동의, 사전 안전 승인, Teen 가드레일의 긴 설명을 제거하고 입력창에 “제안은 공개됩니다.” 한 줄을 표시한다. 안전 심사 상태를 제안 카드나 접수 완료 문구에 붙이지 않는다. 이 화면 정리가 원문을 즉시 개발 명령으로 실행하거나 검증 없이 게임을 공개한다는 뜻은 아니다. 개발·실행의 안전 정책은 [별도 기준](participation-safety.md)에서 관리한다.
- 영어를 기본으로, 한국 접속은 한국어로 자동 표시하고 우측 상단에서 수동 선택한다. 실제 게임의 HUD·조작 안내·일시정지·새 버전 안내도 [언어 지원 기준](localization.md)을 따른다. 언어를 바꿔도 진행 중인 판·세이브·제안 초안을 초기화하지 않는다.
- 검증 전에 실패하면 정상 게임을 유지하고, 공개 후 장애에는 마지막 정상 게임으로 복귀한다. 최초 게임이 없으면 준비 화면과 지연 안내를 유지한다. 게임·제안·세이브 기록을 삭제하지 않는다.

## PC와 모바일 배치

| 환경 | 게임과 제안창 | 조작 기준 |
| --- | --- | --- |
| 넓은 PC 화면 | 왼쪽 게임, 가운데 투표와 그 아래 제안창, 오른쪽 기여도 순위 | 16:9 화면에서 핵심 영역을 함께 표시, 게임 비율 유지 |
| 모바일·좁은 화면 | 게임 → 투표 → 제안 입력 → 기여도 순서의 한 페이지 | 세로 스크롤과 터치 조작, 가로 회전 강제 없음 |
| 게임 확대 | 사용자가 선택한 동안 게임에 집중하고 제안창으로 돌아가는 동작 제공 | 입력 중인 초안을 보존하고 확대 해제로 기본 배치 복귀 |

9:16은 **게임 실행 영역**의 가로:세로 비율이다. 웹페이지 전체를 9:16으로 고정하지 않는다. PC에서도 같은 게임 규칙과 세로 시야를 유지하고 주변 여백을 허용한다. 작은 모바일 화면에는 게임 영역을 비율대로 축소하고, 터치 버튼과 핵심 정보는 읽고 누를 수 있는 크기를 유지한다. 게임 조작을 호버나 키보드 전용 동작에 의존시키지 않는다.

현재 준비 페이지부터 모바일에서 카운트다운·설명·로그인·신규 제안·수정에 접근할 수 있게 한다. PC 전용 차단 안내는 없다. 모바일 가상 키보드, 한글 조합, 긴 문장, 로그인 모달, 화면 회전과 안전 영역을 고려하며 입력 글꼴은 최소 16px을 기본으로 한다. 미국 국기·태극기의 언어 선택과 로그인·관리자·로그아웃은 320px에서도 한 줄 헤더에 남긴다. 주요 터치 영역은 44px 이상이다.

PC 검증 크기는 1280×720, 1366×768, 1600×900, 1920×1080이다. 60px 헤더, 간단한 소개·공개 목표와 카운트다운, 세 열의 작업 영역, 하단 4단계 개발 줄을 기본 상태에서 문서 스크롤 없이 표시한다. 문서의 `overflow:hidden`으로 필요한 내용을 자르지 않는다. 운영 공지·오류·큰 글꼴이나 사용자가 늘린 입력창으로 공간이 더 필요하면 자연스러운 문서 스크롤을 허용한다.

최근·인기 의견은 각각 3개씩 페이지로 나눈다. 카드 원문은 2~3줄 미리보기이며 “원문” 버튼으로 전체 내용을 연다. 이전·다음 버튼과 페이지 번호를 제공하고 숨긴 원문을 몰래 수정하지 않는다. 내 제안은 입력창의 “내 제안” 버튼으로 별도 창에서 확인하고 수정한다. 로그아웃과 계정 변경 시 개인 창과 내용을 즉시 비운다. 긴 원문은 별도 창 안에서 읽을 수 있게 하고, 서버의 원문·별명·점수는 HTML로 해석하지 않는다.

투표 영역의 “더보기”는 전체 공개 의견을 탐색하는 큰 모달을 연다. 최근·인기순 전환과 24개 단위 이전·다음 페이지, 새로고침, 읽기 실패 시 재시도를 제공한다. 넓은 화면에서는 여러 열의 카드로, 모바일에서는 화면 폭에 맞춰 표시하고 모달 안에서 스크롤한다. 카드의 원문 읽기·찬반 투표·내 의견 배지는 메인과 같은 동작을 사용한다. 내 의견에는 투표할 수 없으며, 로그인하거나 목록을 바꾼 것만으로 표를 쓰지 않는다. 원문 창을 닫으면 의견 목록으로, 전체 모달을 닫으면 더보기 버튼으로 초점을 돌려주며 작성 중인 제안을 보존한다.

카운트다운에는 일 단위를 두지 않고 남은 총 시간·분·초를 표시한다. 영어 배포 목표는 워싱턴 D.C. 현지 시각, 한국어는 한국시간으로 표시한다. 두 표시는 같은 절대 시각이며 실제 공개 여부는 계속 서버의 검증된 공개 상태로 판단한다.

기여도 순위는 상위 5명과 여섯 번째의 내 순위 행으로 구성한다. 상위 5명 안에 있더라도 내 행은 유지하고, 참여자가 적으면 빈 공간만 둔다. 전체 순위는 더보기 모달에서 20명씩 확인한다. 내 행에서 공개 별명을 변경할 수 있고 Google 이름·계정·기여 이력은 바꾸지 않는다. 비로그인 방문자에게는 내 순위를 확인할 로그인 동작을 제공하지만 작성 중인 제안을 자동 전송하지 않는다. 내 의견에는 명확한 배지를 표시하며 찬반 투표를 비활성화한다. 새 모달도 언어 전환·키보드 닫기·초점 복귀·모바일 내부 스크롤을 지원하고 데스크톱 기본 배치의 한 화면 조건을 유지한다.

## 공개 상태에 따른 변화

운영 주소는 유지하고 실제 공개 상태에 따라 중심 내용을 바꾼다.

| 상태 | 주된 화면 | 제안과 상태 표시 |
| --- | --- | --- |
| 첫 게임 공개 전 | 흰 9:16 미리보기, 로그라이크 소개, 첫 공개 카운트다운, 제안 입력, 개발 흐름도 | 모집 상태와 접수 가능 상태, 최근·인기 의견과 실제 기여도 순위 표시 |
| 첫 게임 공개 후 | 9:16 게임 실행 영역, 현재 제공 버전, 조작 안내 | PC는 옆, 모바일은 아래 제안창에 남은 횟수·바이트·수집 마감·본인 제안 표시 |
| 다음 버전 제작·검증 중 | 정상 게임을 계속 플레이 | 다음 공개 목표와 제작 상태를 표시하되 성공으로 단정하지 않음 |
| 업데이트 실패 | 마지막 정상 게임을 제공 | 실패한 시도와 현재 제공 버전을 구분해 안내 |
| 운영 점검·종료 | 운영자가 정한 점검·종료 안내 | 신규·수정 제안과 새 개발·공개 중지, 로그인·관리자 복구 접근 유지 |

공개 후에는 긴 첫 모집 소개와 첫 공개 카운트다운을 화면의 중심에서 내리고 게임이 중심이 되게 한다. 개발 흐름 설명은 필요할 때 확인할 수 있게 남긴다. 관리자 기능은 별도의 보호된 `/master`에서 제공하며 기존 `/admin` 링크는 새 주소로 연결한다.

투표·기여도는 메인의 최근 의견·인기 의견과 기여도 순위로 연결한다. 별도 제안 공개 동의·비공개 전환 및 리더보드 공개 설정 버튼은 제공하지 않는다. Google 이름·이메일을 공개 별명으로 사용하지 않으며 과거에 동의하지 않은 기록을 동의한 것처럼 바꾸지 않는다. 모바일의 9:16 게임을 가리거나 초안을 잃게 하지 않는다. 투표 예산·공개 범위·실제 반영 이후 보상은 [별도 기준](voting-and-contribution.md)과 [API](community-api.md)를 따른다. 미연결된 게임 공개 검증을 우회해 점수를 주거나 빈 목록에 예시 계정·점수를 채우지 않는다.

## 플레이와 입력의 기본 동작

배치 승인에 이어 구현할 때 적용할 기본값이다. 실제 게임이 없는 현재 준비 화면에 일시정지·게임 확대 기능이 이미 있다고 표시하지 않는다.

- 기본 PC 화면은 게임 영역과 오른쪽의 투표·제안창을 나란히 둔다. 모바일에서는 같은 페이지에서 투표 다음 제안창으로 이동한다.
- 제안창에 입력하거나 로그인 모달을 열면 게임을 일시정지하고 조작 입력을 차단한다. 한글 입력, Space·Enter·방향키가 게임 조작과 동시에 실행되지 않게 한다. 게임을 재개하는 행동은 분명한 버튼으로 제공한다.
- 모바일에서는 가상 키보드로 게임을 가리더라도 초안과 일시정지 상태를 유지한다. 입력창에서 벗어난 것만으로 재개하지 않고 재개 버튼을 제공한다.
- 한 판 종료 후에 제안창을 강조할 수 있지만 제출을 강제하지 않는다. 로그인만으로 작성 중인 제안을 전송하지 않는다.
- 플레이 중 새 버전이 공개되어도 강제 새로고침하거나 진행 중인 버전을 바꾸지 않는다. 새 버전 안내와 전환 행동을 제공하고 버전별 세이브는 분리한다.
- 아카이브는 플레이 전용이다. 제안 대상은 현재 제공 버전임을 명시한다. 초안 작성 중 현재 제공 버전이 바뀌면 이전 대상을 표시하고 사용자가 확인한 뒤 전환하게 하며 초안을 조용히 다른 버전에 붙이지 않는다.

## 화면 구현 전에 필요한 연결

현재 `/api/status`는 `game.published=false`를 반환하며 실제 게임 선택·산출물·세이브·실행 신호는 없다. 자정 도달이나 HTML 변경만으로 게임 화면을 공개해서는 안 된다. 검증된 게임의 식별자·실행 주소·현재 제공 버전과 제작 상태를 서버의 공개 상태로 연결해야 한다.

게임과 제안창을 같은 화면에 두더라도 실행 권한은 분리해야 한다. 현재 보안 정책은 Google 외 게임 프레임을 허용하지 않으며, 생성 게임을 계정 화면의 스크립트로 합치면 제안 초안과 계정 API에 접근할 수 있다. 게임 실행 영역을 계정·제안 영역과 다른 출처로 격리하고, 필요한 로딩·일시정지·재개·종료 신호만 검증하여 전달하는 설계를 먼저 적용한다. 실제 실행 주소와 세이브 중계 방식은 아직 확정하지 않았다.

공개 성공, 현재 제공 게임, 플레이 중인 게임, 제안 대상 회차·버전은 서로 다른 값이다. 새 공개나 복귀로 로그인 세션·제출 횟수·제안·버전별 세이브를 되감지 않는다. 첫 게임 구현 때 [공개 실행 절차](launch-runbook.md)와 [실패 복귀 규칙](deployment-flow.md)을 함께 검증한다.

## 첫 게임 검증 기준

PC 키보드와 모바일 터치 양쪽에서 9:16 표시·시작·플레이·종료·입력 중 정지·재개를 검증한다. 좁은 화면과 가상 키보드가 열린 상태에서도 제안 초안·남은 횟수·오류 안내를 확인할 수 있어야 한다. 이미 합의한 비로그인 플레이, Google 제출, 제출 제한, 강제 버전 전환 금지와 세이브 분리는 유지한다.
