# 투표와 기여도 설계

상태: 2026-08-31 최신 요청에 따라 제안은 별도 공개 동의·안전 승인 없이 저장 즉시 공개/투표하고, 접수 콘텐츠 사전 필터를 적용하지 않는다. 생성 별칭과 기여도 리더보드도 기본 공개한다. 기존 명시적 숨김은 보존한다. 별도 공개 신원·원자적 투표·조회용 기여도 원장은 유지하며 배포·검증 상태는 [인프라 기록](infrastructure-status.md)에 남긴다. 실제 게임 개발에는 [참여 안전 기준](participation-safety.md)의 Teen 심사와 injection 방어를 유지하며, 신뢰된 게임 공개·반영 증거 발급 경로가 없어 현재 점수 발행은 차단한다.

## 요청으로 정해진 방향

- 제안 후에도 다른 사람의 의견을 읽고 찬성·반대하며 참여할 수 있게 한다.
- 제안 제출 횟수와 별개로 회차당 찬반 합산 3개의 활성 투표권을 부여한다.
- 자신의 요구가 실제로 반영될 때마다 **기여도**를 얻고 공개 성과를 리더보드로 보여준다.
- 표현이 다르거나 일부만 반영되더라도 실질적인 기여가 확인되는 여러 제안자 모두 보상할 수 있어야 한다.
- 채택된 요구를 미리 지지한 투표자에게도 더 작은 기여를 인정한다.
- 찬성표가 많은 안전한 요구는 개발 선택에서 더 높은 가중치를 받는다.
- 인기·기여도·투표권으로 Teen 기준, 안전 승인, 인증이나 운영 권한을 우회할 수 없다.

이 요청은 이전의 “공개 집계 통계만 제공하고 참여자 순위는 표시하지 않음”을 확장한다. 제안 원문과 별칭별 기여도 순위를 공개하되, 내부 심사 이유·Google 개인정보까지 공개한다는 뜻은 아니다. 기존의 서로 양립하는 유효한 요구를 가급적 폭넓게 반영한다는 원칙도 유지한다.

## 화면 구성

PC에서는 9:16 게임 미리보기 옆에 제안 입력창을 두고, 최근 의견·인기 의견과 기여도 리더보드를 메인 화면에서 함께 읽을 수 있게 한다. 최근·인기 의견은 각각 최대 6개, 리더보드는 상위 10명을 보여준다. 모바일에서는 미리보기 아래에 제안 입력창과 커뮤니티 영역을 배치한다. 기본 언어는 영어이며 한국 접속 시 한국어, 우측 상단의 수동 언어 선택을 지원한다. 언어 변경으로 작성 중인 제안이나 로그인 상태를 지우지 않는다.

현재 미리보기는 실제 흰색 `<canvas>`이며 실행 가능한 게임이 아니다. 화면에 이 상태를 설명하고 `game.published=false`를 유지한다. 날짜 도달·웹사이트 배포 성공·흰 캔버스 표시만으로 게임 공개나 채택 성공을 만들지 않는다. 게임 공개 후의 확대·플레이 상태·다음 버전 처리는 [플레이 화면 설계](play-and-propose.md)를 따른다.

처음에는 댓글·쪽지·외부 링크·이미지 업로드 없이 텍스트 제안, 찬반 표시, 내 점수와 채택 횟수를 제공한다. 상세 반영 이력은 실제 발행 경로와 함께 연결한다. 신고는 반대표와 분리한다. 익명 방문자는 공개 제안을 읽을 수 있고 실제 투표에는 Google 로그인이 필요하다. 원문은 실행 가능한 HTML이나 명령이 아닌 텍스트로 표시한다.

최근 목록은 작성 시각 내림차순으로, 인기 목록은 유효 찬성 수에서 반대 수를 뺀 값, 찬성 수, 작성 시각 순서로 정렬한다. 마지막 동점은 공개 ID로 고정한다. 인기 점수와 기여도는 서로 다르며 인기순이 채택을 확정하지 않는다. 찬성·반대 집계는 구분하되 개인별 투표 내역을 다른 사람에게 공개하지 않는다. 리더보드는 별도 생성 별명·확정 점수·채택 횟수만 기본 공개하고 명시적 숨김과 회원 정지를 반영한다. 비공개 참여자도 자신의 점수를 확인할 수 있다. 표시할 참여자가 없으면 빈 상태, 실제 점수가 없으면 0점으로 표시하며 가짜 참여자나 점수를 넣지 않는다.

## 투표권과 회차

처음에는 실제 최초 모집 회차만 연다. 제안과 투표의 마감은 **2026-08-31 23:00 한국시간**이다. 이후 제안의 임시 `pending` 저장값은 투표 회차가 아니며 무기한 3표를 부여하지 않는다. 다음 회차의 ID·시작·마감이 별도로 정해질 때까지 다음 제안의 투표는 대기한다.

| 항목 | 적용 동작 | 이유 |
| --- | --- | --- |
| 지급 단위 | 실제 수집 회차마다 3개, 미사용분 이월 없음 | 긴 접속 시간보다 이번 변화에 대한 선택에 집중 |
| 차감 | 찬성·반대 합산 활성 투표 3개 | 찬반을 각각 3개로 주어 총 6개가 되지 않음 |
| 대상 | 다른 작성자의 현재 공개 revision에 1표. 안전 승인 불필요 | 자기 투표, 같은 제안 양방향 투표·중복표 방지 |
| 변경·취소 | 회차 마감 전 가능. 취소는 사용 중인 슬롯 반환 | 잘못 누른 투표를 고칠 수 있음 |
| 마감 | 제안과 투표·가중치의 고정 시각을 동일하게 적용 | 결과를 본 뒤 편승하는 투표 방지 |
| 회원 정지·명시적 비공개·운영 제외 | 새 투표 금지, 현재 선택 집계에서 제외 | 회원·운영 및 숨김 선택을 준수 |
| 게임 안전 심사 변경 | 공개 및 기존/새 투표에 영향 없음 | 개발 입력 허용과 공개 참여를 분리 |
| 동시성 | 계정·회차별 원자적 예산 검사와 요청 중복 방지 | 여러 탭·기기·재시도로 3개를 넘기지 못함 |

비로그인 상태에서 찬반 버튼을 누르면 Google 로그인 모달을 연다. 로그인 뒤에는 최신 회차·대상·남은 표를 표시하고 사용자가 다시 눌러 확인하게 한다. 로그인·언어 변경·화면 새로고침만으로 투표하지 않는다. 기존의 명시적인 제안 전송 후 로그인 시 제안 한 번 자동 접수 흐름은 별도로 유지한다. 전송 결과가 불확실하면 동일 요청 ID와 동일 내용으로만 재시도한다.

제안 수정이 접수되면 새 본문을 같은 저장 트랜잭션에서 즉시 공개하며 별도 동의/승인이 필요하지 않다. 명시적으로 숨긴 제안은 숨김을 유지한다. 기존 공개 revision에 대한 투표는 새 내용으로 승계하지 않는다. 기존 표는 이력에 남기고 현재 집계에서 빠지며, 해당 회차가 열려 있을 때 활성 슬롯을 반환한다. 수정 전에 이 영향을 작성자에게 알린다. 비공개·재공개, 계정 정지·복원, 운영 제외·복원 뒤에도 옛 표는 자동 부활하지 않는다. 새 투표는 현재 본문/hash·공개 generation·작성자/투표자 회원 제어·운영 검토 revision에 연결한다. 안전 심사 승인·보류·차단·재승인만으로는 현재 표를 무효화하지 않는다.

공개·투표 요청은 Google 인증과 같은 출처의 요청, CSRF 검증을 거친다. 계정당 고정된 1분 구간에 최대 30번으로 별도 요청 빈도를 제한한다. 제안 제출의 60분 3회 제한과 투표의 회차당 활성 3표 예산은 서로 소모하지 않는다. 서비스 점검·종료·참여 중단 시 새 공개 및 투표를 금지하되, 정상 로그인한 작성자의 비공개 전환은 허용한다. 비공개 전환은 원문 삭제가 아니다.

## 기본 공개와 익명성

새 제안과 수정은 기본 공개하며 접수 전에 이를 분명히 알린다. 최신 사용자 지시에 따라 기존 미선택 비공개 제안과 별칭도 `public-default-v1` 서비스 정책으로 전환한다. 작성자의 실제 공개 동의로 위장하지 않고 기본 정책 출처와 별도 시스템 이력을 기록한다. 과거 명시적 숨김은 보존하고, 뒤에 다시 보이도록 명시적으로 선택했다면 최신 선택을 적용한다. 초기화/백필 재실행과 본문 수정만으로 숨긴 제안을 되살리지 않는다. 비공개 제안도 안전 검토·채택 대상일 수 있지만 다른 사용자의 표를 받지는 않는다.

Google의 이름·이메일·sub·프로필 사진을 공개 별명으로 자동 복사하지 않는다. 공개용 무작위 식별자와 `Player-` 뒤 12자리 16진수로 구성된 별명을 별도로 생성한다. 이름을 자유 입력받거나 원문에서 추출하지 않는다. 제안 공개와 리더보드 노출의 명시적 숨김 선택은 별개로 보존한다. 비공개 전환은 피드·현재 투표 집계에서 즉시 제외하고 원문/감사 이력은 보존한다. 탈퇴 시 감사 기록의 보존 기간 등은 개인정보 운영 정책과 함께 정해야 한다.

## 유사도, 충족 여부와 점수

유사도는 **검토할 관련 요구를 찾는 도구**다. 높은 문장 유사도는 채택이나 보상의 증거가 아니다. 예를 들어 “회복 물약을 없애자”와 “회복 물약을 추가하자”는 단어가 거의 같아도 반대되는 요구다. “더 재미있게”, 게임 기능을 전부 나열한 문장, 이미 존재하는 기능을 그대로 복사한 제안에 자동 보상하지 않는다.

반영 판단은 다음 순서로 한다.

1. 안전 승인된 원문 revision과 개발용 정리문에서 구체적으로 확인할 수 있는 요구를 분리한다.
2. 같은 변화인 요구는 하나의 묶음으로 연결하고, 반대·조건부 요구는 구분한다. 같은 계정이 반복 제안해도 같은 요구의 지지와 기여가 늘어나지 않는다.
3. 공개할 게임의 변경점·실행 검증에 요구별 충족 근거를 연결한다. 원문을 읽고 점수를 주라는 지시는 근거가 아니다.
4. 실제 공개 성공 뒤 완전 반영·실질적 일부 반영·미반영을 기록한다. 유사도만 높거나 앞으로 만들 계획인 것은 미반영이다.
5. 같은 공개 버전·요구·참여자의 지급 키로 중복 지급을 막고, 여러 실제 제안자에게 각각 기여를 인정한다.

예를 들어 A가 “매번 다른 지형과 밤낮 변화”, B가 “랜덤 맵”을 제안했고 실제 게임에 지형 변화만 공개됐다면 A의 일부 요구와 B의 요구가 함께 반영될 수 있다. A만 최초 작성자라는 이유로 B를 배제하지 않는다. 반대로 C가 “랜덤 맵을 없애자”고 썼다면 같은 단어 때문에 보상하지 않는다.

최소 반영 기준은 문장의 몇 퍼센트가 겹쳤는지가 아니라 **검증 가능한 요구 하나 이상이 실제 변화에 기여했는가**다. 모호한 경우 임의 유사도 임계값으로 확정하지 않고 검토 보류한다. 모델 버전·요구 분리 기준·판정 근거를 기록하고 이의를 검토할 수 있게 한다. 유사도·반영 정도 산정 모델은 아직 연결하지 않았으며 정확도를 측정한 것처럼 임계값을 표시하지 않는다.

## 요청된 기여도 배점

사용자의 최신 배점 지시가 기존 100/50점·투표 20%·회차 300점 상한 추천을 대체한다. 점수는 현금·아이템 교환·추가 운영 권한이 없는 참여 성과다.

| 대상 | 사용자 지정 식과 현재 상태 |
| --- | --- |
| 채택 제안의 작성자 | 기본 100점에 `upvote**{5}`를 더하고 `downvote**{2}`를 뺀다. 제곱 표기인지 표당 +5·−2점인지 확인 중이다. |
| 채택 제안을 마감 전에 유효하게 지지한 투표자 | `10 + upvote × 1 − downvote × 0.5` |
| 단어만 유사·이미 있던 기능 복사·미반영 | 지급 대상 아님 |
| 반대표, 마감 뒤 찬성, 무효 투표 | 투표 기여 지급 대상 아님 |

제안자 식의 해석은 임의 확정하지 않는다. 예를 들어 찬성 3표·반대 2표는 제곱 해석이면 339점, 표당 가중치이면 111점이다. 확인 전에는 공개 정책을 `pending_confirmation`, `policyVersion=null`로 두고 후보 계산은 반드시 `weighted` 또는 `exponent`를 명시한 미리보기로만 제공한다. 브라우저는 후보 하나를 이미 확정된 배점처럼 표시하지 않는다. 두 해석의 계산 코드는 0.5점 단위 정수로 정확히 처리하며 큰 점수, 음수, 소수점 0.5를 반올림하거나 0점으로 자르지 않는다.

찬반 수는 해당 실제 변화에 연결된 안전한 제안과 유효 참여자를 중복 제거한 마감 스냅샷에 근거해야 한다. 사용자가 전달한 찬반 수·점수·채택 여부는 지급 근거가 아니다. 점수식을 확정해도 실제 공개·충족 증거가 없다면 발행은 계속 차단한다.

같은 참여자·요구 묶음에는 한 번만 지급한다. 유사 제안 세 개를 올리거나 여러 복제 제안에 표를 던져도 같은 반영 성과를 여러 번 벌지 못한다. 자신의 요구 묶음으로 제안 기여를 받는 사람이 그 묶음의 다른 글에도 찬성했다면 더 큰 제안 기여만 적용하고 투표 기여를 중복 지급하지 않는다.

기존에 제안했던 회차당 300점 상한이나 일부 반영 50점, 투표자 20%는 적용하지 않는다. 검증 가능한 요구 하나 이상이 실제 변화에 기여하면 관련 작성자들의 기여를 인정하되, 단일 글을 수십 개의 작은 요구로 쪼개는 방식은 같은 실질적 변화로 묶는다. 다중 Google 계정을 자연인별로 완전히 중복 제거할 수 없으므로 신규 계정 간 집중 상호 투표·동일 내용·비정상 속도는 별도 이상 징후로 확인하고 자동으로 유죄로 단정하지 않는다.

이미 지급된 변화가 다음 버전에 그대로 남아 있다고 다시 지급하지 않는다. 이전에 미반영된 부분이 나중에 새로 충족되면 그 추가 성과만 기록한다. 기술 장애로 정상 버전에 잠시 복귀했다고 기여도를 자동 몰수하지 않는다. 허위·부정·잘못된 판정의 정정은 이유 있는 조정 원장으로 남기며 과거 지급을 삭제·재사용하지 않는다.

현재 선택 정책의 “기존 기여자” 보너스는 자기 제안이 실제 반영된 자격을 뜻한다. 투표 기여 점수만으로 이 보너스를 새로 얻거나 누적 기여도만큼 채택 가중치가 계속 커지도록 바꾸지 않는다. 리더보드 상위권이 이후 결과를 독점하는 순환을 제한한다.

## 찬반과 개발 선택의 관계

먼저 안전·로그라이크 경계·현재 버전 유효성·구현 가능성을 검사한다. 그 뒤에만 지지를 비교한다. 과격한 제안을 많은 계정으로 밀어 올려도 안전 승인·공개 검증을 건너뛸 수 없다.

기존 합의는 제안자의 기본 1점에 플레이타임과 기존 제안 기여자 보너스를 합산한다. 이를 확장할 추천안은 별도 찬성 투표자의 가중치에 0.5를 곱해 추가하는 방식이다. 같은 참여자가 같은 요구의 작성자이면서 찬성자이거나 복제된 여러 글에 투표해도 가장 큰 한 번의 지지만 반영한다. 활동 시간 검증이 아직 없다는 사실은 기존과 같다.

반대표는 최신 요청에 따라 **인기 목록의 순위와 채택 뒤 기여도 식**에 반영한다. 이것이 안전 심사상 자동 제외나 개발 선택의 자동 거부권을 뜻하지 않는다. 반대표에도 3개 예산을 사용하며 신고나 안전 위반 판정과 혼동하지 않는다. 실제 개발 선택의 찬반 가중 계수는 아래 기존 합의와 별도로 검증해야 한다.

안전한 요구끼리 충돌할 때 합산점수, 플레이타임 가중점수, 완전 동점 시 고정된 추첨 순서를 유지한다. 서로 충돌하지 않는 요구를 인기 상위 몇 개로 제한하지 않는다. 자동 선택·투표 가중치 코드는 아직 구현하지 않았으므로 이 추천 수식을 현재 서비스의 동작으로 표시하지 않는다.

## 필요한 데이터와 검증 순서

| 기록 | 핵심 연결과 제한 |
| --- | --- |
| 실제 수집 회차 | 고유 ID, 대상 게임, 시작·마감 시각. 임시 `pending`이나 배포 시도 ID와 구분 |
| 공개 제안 revision | 현재 원문 revision/hash·공개 generation·기본 정책 또는 명시적 선택·별도 공개 식별자. 불변 내용과 수정 이력 |
| 투표와 변경 이력 | 계정·회차·공개 revision·방향·시각·요청 ID, 활성 예산 최대 3 |
| 요구 묶음 | 관련 원문·반대 관계·중복 제거·판정 버전. 단순 텍스트 해시로 의미 동일성을 주장하지 않음 |
| 반영 판정 | 실제 공개 게임·변경점·실행 증거·충족 요구·정도, 심사자와 정책 버전 |
| 기여도 원장 | 지급·조정 이벤트, 중복 방지 키, 제안/투표 기여 구분. 클라이언트 총점 신뢰 금지 |
| 리더보드 | 생성 별명·확정 기여도만 기본 공개. 명시적 숨김·정지 반영. 이메일·내부 메모 없음 |

게임 개발용 안전 심사·원문 revision 보존 위에 실제 최초 회차·서비스 기본 공개 정책·별도 공개 신원·원자적 투표와 리더보드 조회를 둔다. 기여도 원장은 실제 공개 영수증·소스 및 자산 digest·충족 근거·원문 revision·안전 및 점수 정책·고정 투표 스냅샷을 연결하도록 준비한다. 수정·삭제·같은 지급 키로 덮어쓰기하지 못하게 보존한다. 아직 신뢰할 발행기가 없으므로 `settle`은 항상 `RELEASE_REVIEW_UNAVAILABLE`로 거절하고, 공개 API·관리자 JSON에는 점수 발행이나 채택 성공 액션을 두지 않는다.

현재 조회 구현은 최대 50,000행을 정확한 정수로 합산한다. 이를 초과하면 부정확한 순위를 반환하는 대신 명시적으로 실패한다. 실제 발행기를 연결하기 전에는 이 제한에 의존하지 않는 정확한 누적 조회 모델과 정정 원장을 함께 마련해야 한다. 아직 채택 기록이 없으면 정직한 빈 상태 또는 실제 0점을 보여주며 테스트 점수나 가짜 기여자를 운영에 넣지 않는다. 구체적인 경계는 [커뮤니티 API](community-api.md)를 따른다.

필수 검증에는 여러 기기의 동시 네 번째 표, 재전송 중복, 자기·정지 계정 표, 즉시 공개와 명시적 숨김 보존, 수정·마감 경쟁, 안전 심사 변경 후 표 유지와 개발 입력 차단, 구/신 배포 혼합 쓰기, 공개 상태 저장 실패 시 본문 동시 롤백, 중복 요구 보상, 반대 의미 오분류, 공개 실패·재시도·복귀 시 중복 지급, 점수 조작을 지시하는 본문이 포함된다.

## 남은 연결과 확인

제안자 식의 `**` 해석을 확인한 후 점수 정책 버전을 확정한다. 실제 게임 공개·요구 충족 판정·마감 스냅샷의 신뢰 가능한 발행 경로, 다음 실제 수집 회차, 부정 참여 검토·이의 및 정정 절차는 별도로 연결해야 한다. 기본 공개 안내와 명시적 숨김/개인정보 보호, 게임 개발용 안전 승인, 실제 공개 후에만 지급, 서버 중복 방지 원칙은 점수식과 무관하게 유지한다.
