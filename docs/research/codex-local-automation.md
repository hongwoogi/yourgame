# Codex 구독을 사용하는 로컬 자동화 검토

상태: 문서 조사 및 로컬 읽기 전용 확인. 게임 자동화 구현·운영 승인이 아니며 실제 Codex 모델 작업, 웹훅, 예약 실행, 유료 API 호출 또는 결제 설정 변경은 수행하지 않았다.

## 사용자 요구

- 이미 구독 중인 Codex 환경을 이용한다.
- 웹에서 모인 제안을 정리해 사용자의 컴퓨터로 처리 요청을 전달한다.
- 별도 유료 API 대신 구독 사용량 안에서 처리하기를 원한다.
- 하루 추가 AI 비용 한도는 1,000원이다.

## 확인한 사실

- 이 PC에 codex-cli 0.150.0-alpha.8이 설치되어 있다.
- codex login status 결과를 민감 정보 없이 분류하여 ChatGPT 로그인을 확인했다. 구독 상품 종류, 남은 사용량, 보유 유료 크레딧과 자동 충전 설정은 확인하지 않았다.
- codex exec --help에서 비대화형 실행, JSONL 출력, 결과 스키마, 작업 디렉터리와 sandbox 선택 기능을 확인했다. 실제 게임 작업 또는 모델 호출은 수행하지 않았다.
- 공식 문서에서 codex exec는 스크립트·CI·예약 작업용 비대화형 실행이며 저장된 CLI 인증을 재사용한다고 설명한다. 따라서 기존 ChatGPT 인증으로 로컬 실행을 시작하는 기술적 경로가 있다. [비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode)
- 공식 app-server는 ChatGPT 인증과 작업 제어 및 account/rateLimits/read를 제공한다. 단순 작업에는 exec, 지속적인 상태·사용량 확인에는 app-server를 검토할 수 있으나 어느 방식도 아직 구현하지 않았다. [App Server](https://learn.chatgpt.com/docs/app-server)
- 구독 사용량은 다른 Codex 작업과 공유되며, 포함 사용량 이후 보유 크레딧으로 계속할 수 있다. 작업 횟수만으로 비용 또는 포함 사용량 소모를 정확하게 계산할 수 있다고 가정하지 않는다. [요금 및 사용량](https://learn.chatgpt.com/docs/pricing)

## 지원 범위와 확인되지 않은 부분

- 공식 인증 문서는 신뢰하지 않는 공개 환경에 Codex 실행을 노출하지 말라고 경고한다. 공개 이용자가 임의 Codex 작업을 실행하는 서비스와 운영자 본인의 게임 저장소를 유지보수하는 정기 작업은 구분한다. 확인한 기술 문서만으로 이 서비스 형태의 계약상 허용 여부를 보증하지 않는다. [인증 안내](https://learn.chatgpt.com/docs/auth)
- ChatGPT 인증을 유지하는 공식 CI/CD 가이드는 신뢰하는 비공개 자동화를 다루며, 해당 인증 전달 워크플로를 공개 또는 오픈소스 저장소에 사용하지 말라고 명시한다. 이는 그 CI/CD 워크플로에 관한 조건이며 공개 웹 게임 전체가 금지된다는 의미로 확대하지 않는다. 현재 설계에서도 구독 인증 자료를 서버·저장소·웹훅에 업로드하는 방식은 채택하지 않는다. [CI/CD 인증 가이드](https://learn.chatgpt.com/docs/auth/ci-cd-auth)
- API로 자동 전환된다는 동작은 확인되지 않았다. 포함 사용량이 끝날 때 exec가 반드시 별도 동의를 받고 크레딧을 사용한다거나, 포함 사용량만으로 강제 정지시키는 기능도 확인하지 못했다.
- forced_login_method=chatgpt 설정은 인증 방식을 제한하며 유료 크레딧 사용 차단 장치로 취급하지 않는다. [설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference)
- 따라서 추가 비용 0원 또는 하루 1,000원 절대 상한이 이미 보장된다고 기록하지 않는다. 한 작업 도중 포함 사용량 경계를 넘어가는 경우까지 제어할 방법을 실제 설정과 동작으로 확인해야 한다.

## 권장 구조 — 사용자에게 제시할 설계안

웹 제안 접수 → 서버 DB에 회차별 확정 작업 보관 → 개인 PC가 인증된 비공개 대기열을 조회 → 제한된 Codex 작업 1건 실행 → 로컬 검증 → PC 측에서 GitHub push → Vercel Git 연동 빌드·배포 → 실제 공개 결과 확인.

GitHub push로 Vercel 배포를 유발하는 방식은 사용자가 수락했다. Vercel Cron은 사용하지 않으며, 매 회차 사람의 클릭이 필요하다는 뜻은 아니다. push와 실제 공개 사이에는 빌드 시간이 있으므로 구체적인 공개 시각 정책은 설계 기록에서 별도로 확인한다. 운영 브랜치 설정과 공개 완료 확인은 [배포 흐름](../deployment-flow.md)에 정리했다.

- 공개 웹훅을 PC의 Codex 실행 인터페이스에 직접 연결하지 않는다. PC가 외부로 접속해 정해진 작업을 가져오는 구조를 권장한다.
- 여러 이용자의 원문 프롬프트는 변경 요구를 담은 입력 자료로 취급하며 운영 규칙이나 실행 권한을 바꾸는 지시로 취급하지 않는다.
- 모델이 필요한 의미 분류와 코딩은 로컬 실행 경로에서 처리한다. 확정된 참여자 점수 산술 집계와 일정 계산은 일반 코드로 처리해 별도 유료 API를 전제하지 않는다.
- 작업을 직렬 실행하고 대상 작업 공간·도구·네트워크 권한을 제한한다. 개인 환경의 모든 파일, 연결 앱, 운영 DB 자격증명 및 배포 권한을 그대로 물려주지 않는다.
- 신뢰하는 별도 배포 단계에서 검증된 결과만 공개한다. 모델이 외부 입력을 받아 운영 규칙이나 배포 자격증명을 변경할 수 있게 하지 않는다.
- PC 오프라인 또는 포함 사용량 부족 시 기존 게임을 유지하고 다음 가능한 정규 회차에서 재개하는 정책은 Q25에서 수락되었다. 인증 만료 및 사용량 확인 실패도 안전하게 중단하는 상세 규칙과 장애 감지 방법은 구현 설계에서 확인해야 한다.
- 유료 API 전환, 추가 크레딧 구매 및 자동 충전을 기본 복구 수단으로 두지 않는다. 한도 확인과 여유분을 통한 예방은 엄격한 결제 상한 차단이 검증되었다는 뜻이 아니다.

운영 문제로 반영하지 못할 때 참여자에게도 상태를 알리며 운영자를 가볍게 놀리는 안내를 사용한다. 문구와 사실 표시 규칙은 [운영 상태 안내](../operations-status.md)를 따른다.

## 다음 검증

- 선택한 운영 형태의 공식 지원 조건과 구독·크레딧 과금 통제를 확인한다.
- 실제 로컬 작업자, 인증된 대기열, 최소 권한 작업 공간, 사용량 검사 및 종료·재시도 동작을 작은 시험 작업으로 검증한다. 현재 인터뷰 단계에서는 실행하지 않는다.
- 한 시간의 구현·검증 시간과 공유 구독 사용량 안에서 얼마나 많은 변경을 처리할 수 있는지 확인한다. 모든 유효 제안의 반영은 목표이며 처리량 보장이 아니다.
